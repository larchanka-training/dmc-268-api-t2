# DMC-268 API (Team 2)

Бэкенд-сервис проекта DMC-268, команда 2. Контекст покрывает каркас API и его эксплуатационные термины.

## Language

### Диагностика

**Healthcheck**:
Проверка живости (liveness): `GET /healthcheck` всегда отвечает `200 OK` и не обращается к зависимостям (БД, Redis).
_Avoid_: `/health`, health check, пинг

**Readiness**:
Проверка готовности: доступность зависимостей (PostgreSQL, Redis) через отдельный эндпоинт. Отдельное понятие, никогда не смешивается с Healthcheck.
_Avoid_: deep healthcheck, расширенный healthcheck

**Request ID**:
Идентификатор корреляции HTTP-запроса: middleware генерирует его на каждый запрос, примешивает ко всем записям журнала и возвращает в заголовке `X-Request-Id`; входящее значение заголовка переиспользуется.
_Avoid_: correlation id, trace id

### Пайплайн

**Worker**:
Фоновый процесс, выполняющий шаги обработки ревью вне HTTP-цикла API. Запускается как отдельный сервис рядом с API и обновляется тем же деплоем.
_Avoid_: бэкграунд-таска, celery-процесс, cron

**Правила репозитория** (repository rules):
Canonical-документ пользовательских правил ревью (`RepositorySettings.rules`); источник истины для правил независимо от носителя. В промпт попадает только как изолированные данные: инструкции из правил не исполняются.
_Avoid_: .review/rules.md (это лишь будущий VCS-носитель), системные правила, user prompt rules

**rule_ref**:
Метка пункта правил репозитория (например, `[SEC-1]` в начале текста инструкции), которую замечание указывает как нарушенную. Может отсутствовать — не каждое замечание обязано ссылаться на правило. Валидность метки проверяется детерминированно: метки извлекаются из переданных правил, ссылки на неизвестную метку отбраковываются.
_Avoid_: rule id, номер правила, ссылка на файл rules.md

**Reflection Pass** (верификатор):
Дополнительный структурированный проход LLM-верификатора, отфильтровывающий замечания, не подтверждённые diff и правилами. Включается настройкой, по умолчанию выключен.
_Avoid_: второй мнус, re-check, повторная генерация

**Цикл ревью** (review cycle):
Одна итерация обработки: вебхук → захват снапшота PR → анализ → публикация ревью на захваченный head. Новый push в PR всегда начинает новый цикл с новым review_id; дедупликация замечаний действует внутри одного цикла, а межцикловые повторы подавляются при публикации счётно по fingerprint'ам и ключам подавления из комментариев прошлых циклов — каждый прошлый inline-комментарий занимает один слот своей идентичности, поэтому повтор (в том числе после сдвига строк между коммитами) называется в корпусе ревью как «уже отмечено», а излишек находок той же идентичности публикуется inline (приёмка #53). Анализ по-прежнему выполняется на полном диффе от merge-base; отсечение уже проверенных участков — направление спринта 4 (dmc-268-ui-t2#28, dmc-268-ui-t2#33).
_Avoid_: инкрементальное ревью (анализ полного диффа не отсекает проверенные участки), итерация ревью

**Fingerprint замечания**:
Идентичность замечания: SHA-256 от нормализованных пути, стороны, диапазона строк, категории и заголовка. Обеспечивает дедупликацию находок внутри одного цикла, межцикловое подавление повторов при публикации и маркер-доказательство в комментариях публикации, по которому повторная доставка распознаётся без записей в GitHub. Межцикловое подавление дополнительно сверяет ключ подавления — SHA-256 от пути, стороны, категории и заголовка без диапазона строк (маркер `dmc268-suppress` в inline-комментарии), поэтому повтор находки после сдвига строк между коммитами тоже не публикуется.
_Avoid_: хэш замечания, ID находки

**Ключ подавления**:
Идентичность замечания без диапазона строк для межциклового подавления: SHA-256 от нормализованных пути, стороны, категории и заголовка. Публикуется рядом с fingerprint в маркере `dmc268-suppress`; повтор по ключу подавляется, если строки сместились между коммитами незначительно (#53): ключ без диапазона не различает сдвиг и второй независимый дефект, поэтому сопоставление по ключу дополнительно сверяет место — путь, сторону и якорь комментария прошлых циклов в пределах 10 строк; кандидат вдали от всех незанятых якорей публикуется inline — неоднозначность решается в пользу публикации (#60). Подавление счётное: каждый inline-комментарий прошлых циклов — один слот идентичности; точные повторы по fingerprint занимают слоты первыми, излишек находок той же идентичности (например, тот же дефект во второй функции) публикуется inline. Собирается при публикации только из хвоста маркеров, публикуемых издателем; маркеры из текста модели вырезаются при рендере (RT-12).
_Avoid_: identity key, suppress hash

### Тестирование

**Chaos-сьют**:
Детерминированные fault-injection тесты (pytest-маркер `chaos`, отдельный job в CI): таймауты и 429 LLM API, сетевые сбои GitHub API и гибель воркера инжектируются фейками на публичных швах при реальных PostgreSQL и Redis.
_Avoid_: хаос-тесты, стресс-тесты
